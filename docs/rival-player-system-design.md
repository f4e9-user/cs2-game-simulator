# 宿敌选手系统设计方案（待实现）

落地日期：2026-06-06

当前分支：dev

状态：待实现，供后续排期

## 1. 设计目标

当前游戏主角是个人电竞选手，不是俱乐部经营者。因此“宿敌”应优先是某个具体选手，而不是一个抽象战队。

本系统需要满足三个目标：

- 与当前赛事系统融合：宿敌应通过赛事相遇、淘汰、复仇、晋级竞争等流程自然出现。
- 玩家必须知道原因：界面和事件文案需要明确说明“为什么这个选手会成为我的对手”。
- 宿敌是个人选手：战队可以作为背景归属，但核心关系应发生在玩家与某个选手之间。

## 2. 当前问题

现有 `Rival` 更接近世界背景中的战队名池：

- 数据上主要是 `name`、`tag`、`region`。
- 事件里常用作 `{rival0}` 等占位符替换。
- 排行榜和部分挖角流程会引用这些名字。
- 赛事模拟没有真正选择一个具体宿敌作为对手。
- 没有宿敌选手的强度、风格、交手记录、仇恨值、尊重值、生成原因。

因此当前对手系统缺少可追踪关系，玩家很难感知“我和谁在竞争，以及为什么竞争”。

## 3. 核心方案

保留现有世界背景战队池，但新增真正的宿敌选手系统。

- `Rival`：继续作为世界背景战队或组织名池使用。
- `RivalPlayer`：新增为实际宿敌关系主体。

宿敌不应默认无理由出现，而应由具体游戏行为生成。例如：

- 玩家在公开赛中淘汰某名新秀。
- 玩家被某名选手在淘汰赛击败。
- 两名选手同位置竞争同一个首发机会。
- 旧队友离队后加入竞争队伍。
- 某选手公开挑衅玩家或在媒体事件中形成冲突。

## 4. 数据模型草案

```ts
interface RivalPlayer {
  id: string;
  handle: string;
  realName?: string;
  region: string;
  teamName: string;
  teamTag: string;
  tier: TournamentTier;
  role: TeammateRole;
  style: RivalPlayerStyle;
  strength: number;
  potential: number;
  fame: number;
  rivalryReason: RivalryReason;
  heat: number;
  respect: number;
  winsVsPlayer: number;
  lossesVsPlayer: number;
  lastMetRound?: number;
  createdRound: number;
}

type RivalPlayerStyle =
  | 'aim'
  | 'igl'
  | 'clutch'
  | 'stable'
  | 'toxic'
  | 'prodigy';

type RivalryReason =
  | 'same-rookie-breakout'
  | 'lost-to-you-in-open'
  | 'knocked-you-out'
  | 'trash-talked-you'
  | 'role-competition'
  | 'poached-teammate'
  | 'former-teammate'
  | 'rival-org-star';
```

字段含义：

- `handle`：选手 ID 或昵称，玩家主要识别对象。
- `teamName` / `teamTag`：宿敌当前所属战队，用于赛事对阵展示。
- `tier`：宿敌活跃赛事层级，应与当前新赛制赛事挂钩。
- `style`：影响事件文案、比赛压力、对局风格。
- `strength`：当前强度，可影响对阵难度。
- `potential`：成长潜力，用于后续赛季或长期宿敌。
- `fame`：知名度，用于媒体、舆论、邀请赛权重。
- `rivalryReason`：生成原因，必须能转换成玩家可读文本。
- `heat`：对抗热度，越高越容易触发相关事件和再次相遇。
- `respect`：互相认可程度，用于区分恶性冲突和良性竞争。
- `winsVsPlayer` / `lossesVsPlayer`：玩家视角交手记录。

## 5. 生成来源

### 赛事生成

赛事是宿敌系统的主入口。

可生成宿敌的场景：

- 玩家输给某个对手，并且该场比赛是淘汰赛或关键晋级战。
- 玩家爆冷淘汰更高强度对手。
- 玩家与同一对手短期内多次相遇。
- 玩家在 B 级或更高赛事中与某个同位置明星选手交手。

生成原因示例：

- `knocked-you-out`：对方在淘汰赛中击败玩家。
- `lost-to-you-in-open`：对方被玩家在公开赛淘汰，形成复仇线。
- `same-rookie-breakout`：同届新秀在同一层级冒头。

### 队伍系统生成

队伍关系可以生成更个人化的宿敌：

- 旧队友转会到竞争队伍。
- 玩家与某个选手竞争同一个首发位置。
- 对方战队挖走玩家队友。
- 玩家被某队拒绝试训后，该队同位置选手成为竞争对象。

生成原因示例：

- `role-competition`
- `poached-teammate`
- `former-teammate`
- `rival-org-star`

### 事件生成

少量事件可以主动制造宿敌，但必须给出明确原因。

示例：

- 媒体采访中某选手评价玩家“不够稳定”。
- 天梯高分段连续撞车同一名选手。
- 训练赛中被同位置选手针对。

事件生成的宿敌不应太频繁，否则会削弱赛事关系的分量。

## 6. 与赛事系统融合

赛事报名或生成待比赛时，需要生成本场对手信息。

```ts
interface MatchOpponent {
  teamName: string;
  teamTag: string;
  difficulty: number;
  rivalPlayerId?: string;
}

interface PendingMatch {
  tournamentId: string;
  tournamentName: string;
  tier: TournamentTier;
  roundName: string;
  opponent?: MatchOpponent;
}
```

赛事对手生成规则：

- 普通比赛生成普通对手。
- 如果存在同层级、热度较高、近期未交手的宿敌，则提高其成为对手的权重。
- 半决赛、决赛、晋级战、淘汰战中，宿敌出现权重更高。
- 宿敌不应每场都出现，避免显得人为安排。
- 宿敌强度可影响 `difficulty`，但不应让赛事难度完全失控。

比赛结算后更新宿敌状态：

- 玩家获胜：`winsVsPlayer + 1`，对方 `heat` 上升，`respect` 可能上升。
- 玩家失败：`lossesVsPlayer + 1`，`heat` 上升，玩家后续复仇事件权重上升。
- 关键淘汰赛：`heat` 增幅更高。
- 连续多次交手：根据胜负差距调整 `respect` 和媒体事件权重。

## 7. 玩家可见信息

宿敌系统必须让玩家明确知道关系来源。

### 宿敌卡片

展示内容：

- 选手昵称、所属战队、位置、地区。
- 风格标签，例如“枪男”“指挥型”“残局专家”“稳定型”“挑衅型”“天才新秀”。
- 宿敌原因，例如“他在 B 级联赛半决赛淘汰了你”。
- 交手记录，例如“你 1 胜 2 负”。
- 热度与尊重值。
- 最近一次交手回合或赛事。

### 比赛预览

如果本场对手包含宿敌，需要展示：

- 对方战队。
- 宿敌选手。
- 本场关系说明。

示例：

```text
对手：Rift Wolves
关键选手：Kaze
关系：他在上次 B 级淘汰赛击败了你，这场是复仇战。
```

### 事件文案

宿敌事件必须引用具体选手，而不是只引用战队。

示例：

```text
Kaze 在采访中提到，你的残局处理还不够成熟。
```

## 8. 事件系统改造方向

现有 rival 相关事件可以从“随机战队氛围事件”改成“具体宿敌选手事件”。

优先改造 2 到 3 个事件：

- 赛前挑衅：高 `heat`、低 `respect` 时触发。
- Demo 复盘：输给宿敌后可触发，提供成长或压力变化。
- 赛后互相认可：多次交手且 `respect` 较高时触发。

事件触发条件建议：

- 必须存在至少一个 `RivalPlayer`。
- 根据 `rivalryReason`、`heat`、`respect`、最近交手时间筛选。
- 事件效果应走当前结构化 `Outcome`，不要新增旁路结算。

## 9. v1 范围

v1 目标是让宿敌“看得见、说得清、能在赛事中相遇”。

建议实现：

- 新增 `RivalPlayer` 数据结构并挂到游戏状态。
- 从赛事结果中生成宿敌。
- `PendingMatch` 增加 `opponent`。
- 赛事对手生成时允许宿敌以权重方式出现。
- 比赛结算后更新宿敌胜负记录、热度、尊重值。
- 增加宿敌卡片或调试入口，先让玩家能看到当前宿敌。
- 比赛预览展示宿敌选手和关系原因。
- 改造少量 rival 事件为具体宿敌事件。

v1 不建议做：

- 复杂转会市场联动。
- 大量宿敌同时成长。
- 宿敌排行榜完整模拟。
- 强制让每个赛事都有宿敌。

## 10. v2 方向

v2 可以强化长期叙事和世界模拟：

- 宿敌成长曲线：宿敌会随赛季成长、转队、升降层级。
- 多宿敌类型：复仇型、互相尊重型、媒体炒作型、同门竞争型。
- 前队友宿敌：队伍系统成熟后，旧队友离队可成为特殊宿敌。
- 转会系统联动：宿敌加入强队后提高赛事相遇权重。
- 排行榜联动：宿敌可以和玩家争夺排名、MVP、入队机会。
- Major 或高级赛事复仇线：高层级赛事中出现历史宿敌会提升压力和奖励。
- 社交媒体事件：由宿敌发言、粉丝争议、解说评价触发事件。

## 11. 平衡原则

- 宿敌应增强赛事记忆点，而不是替代赛事系统。
- 宿敌出现需要有间隔，避免玩家感觉被系统强行安排。
- 宿敌强度可以影响比赛难度，但幅度应受赛事层级约束。
- 宿敌事件不能只惩罚玩家，也应提供成长、声望、复仇收益。
- 恶性冲突和良性竞争都应可存在，分别通过 `heat` 和 `respect` 表达。

## 12. 待定问题

- 同时最多允许几个活跃宿敌。
- 宿敌强度是否直接影响比赛难度，还是只影响压力、奖励和事件。
- 现有 `Rival` 是否后续重命名为 `WorldTeam`，避免与 `RivalPlayer` 混淆。
- 宿敌是否允许退场，例如长期不相遇、层级差距过大、剧情线结束。
- 第一名宿敌是否需要新手引导，还是完全由赛事自然生成。

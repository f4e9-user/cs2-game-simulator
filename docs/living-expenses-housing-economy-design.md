# 居住与早期经济压力设计

状态：已完成。

## 现状说明

当前代码库已经有一套可工作的金钱系统，但它主要由以下部分组成：

- `stats.money` 作为唯一余额。
- 商店购买、贷款、朋友借款、典当、工资结算、赛事奖金、失败惩罚。
- 信用分、破产回合、家人危机等风险分支。

当前已经落地第一版“住宿等级 + 固定生活费 + 周期恢复修正”系统，本文档保留的是该版本的设计口径和后续扩展边界。

## 当前可复用能力

现有系统里，和本设计直接相关的能力有：

- `player.stats.money`：当前余额。
- `applyMoneyTransaction` / `applyMoneyDeltaToStats`：统一资金变动入口。
- `applyForLoan` / `applyFriendLoan`：借贷系统。
- `applyShopPurchase`：商店消费。
- `pawnItem`：典当变现。
- `salaryTracker`：战队工资发放节奏。
- `creditScore`、`consecutiveBrokeRounds`：信用与破产风险。
- `pendingFamilyCrisis`：家庭危机的强制支出。
- `player.stage` / `player.team` / `player.fame`：可以作为后续住房分层和生活成本的约束因子。

这些能力已经和“居住状态”绑定起来，构成了第一版现金流压力闭环。

## 设计目标

- 让 `money` 从开局就成为要管理的资源，而不是只在商店里才有意义。
- 让早期新人阶段持续面对稳定现金压力。
- 让住宿、恢复、训练、打工、贷款形成清晰的资源闭环。
- 让后期购房成为长期投资型选择，而不是纯装饰资产。
- 不破坏当前商店、贷款、工资、典当和赛事奖励系统。

## 非目标

- 第一版不重写现有工资、奖金、贷款、商店逻辑。
- 第一版不引入真实世界复杂税制、按揭、房产升值或多城市房价系统。
- 第一版不要求新增独立 UI 页面来管理房屋。
- 第一版不把住房系统和职业队管理强绑定，避免把两条系统硬耦合在一起。

## 目标结构

### 1. 固定生活开销

目标方案里，每个周进程应有一笔自动扣除的固定生活费，代表：

- 吃饭
- 通勤
- 基础杂费

规则建议：

- 金额稳定存在。
- 早期可承受，但会让新人明显感到压力。
- 不应高到把玩家直接卡死在新手阶段。
- 结算点必须跟当前引擎的周推进一致，不额外引入“日历周”。
- 以当前代码为准，1 个账期按 4 周进程处理，生活费和工资都应在周推进后统一结算。
- 生活费的扣除顺序建议放在工资到账之后、恢复系统之前，避免和危机检查互相打架。
- 固定生活费不包含房租，房租由住宿等级单独计算。

### 2. 住宿等级

目标方案里，住宿应成为一个可升级状态，而不是仅用于文案：

- 宿舍 / 合租
- 普通租房
- 高级公寓
- 购房

住宿等级的作用应当是“长期现金流选择”，而不是短期恢复道具。

建议参数框架：

- 每个住宿档位只维护 3 个核心参数：`基础周支出`、`恢复修正`、`压力修正`。
- 额外收益只做轻量化，例如少量疲劳恢复、睡眠质量提升、社交事件缓冲。
- 早期档位重点是便宜，中期档位重点是稳定，后期档位重点是减少折腾成本。
- 第一版不做按城市浮动房价，也不做复杂面积、物业、通勤距离模拟。

建议档位带宽：

- 宿舍 / 合租：最低支出，几乎不提供修正。
- 普通租房：中低支出，提供轻微恢复修正。
- 高级公寓：高支出，提供稳定恢复和压力缓冲。
- 购房：高一次性成本，低周期开销，附带小幅长期修正。

### 3. 后期房产

目标方案里，购房不只是省钱，还应当带来：

- 周期开销降低
- 少量恢复或压力缓冲
- 一些生活类事件分支
- 更强的身份感和职业阶段感

## 早期经济决策

目标方案里，早期典型取舍应该是：

```text
本周是继续训练，还是先打工凑钱？
是贷款买恢复服务，还是硬撑去打比赛？
是先升级住宿，还是把钱留给下周的赛事和训练？
```

这类决策应该在前 1-2 个职业阶段就持续出现，而不是等到中后期才开始有感。

## 经济压力来源

当前系统里，经济压力已经可以由下列部分共同构成：

### 1. 固定生存费

- 吃饭
- 交通
- 网费
- 基础生活支出

这部分适合做成最稳定、最早期的扣费项。

### 2. 训练相关消费

- 枪法私教
- 战术复盘
- 心理咨询
- 理疗按摩

这类消费非常适合和“成长”“恢复”“压力管理”绑定。

### 3. 赛事成本

- 差旅费
- 住宿费
- 签证费
- 参赛开销

这类成本适合用于后续更高层级赛事或国际赛事。

### 4. 装备维护

- 外设升级
- 维修
- 替换

当前商店已经有外设升级逻辑，可以作为这条支线的基础。

### 5. 战队相关支出

- 队内聚餐
- 团建
- 训练资源分摊
- 违约金

这类支出可以让“加入战队”不是纯收益。

### 6. 社交和品牌成本

- 请客
- 见面会
- 经纪人分成
- 媒体公关

这部分可以和名气挂钩，后续再逐步展开。

### 7. 健康与恢复成本

- 理疗
- 药物
- 休养
- 更好的生活环境

这类支出适合和压力、体能、伤病恢复一起设计。

### 8. 风险性支出

- 贷款利息
- 违约罚金
- 弃赛罚款
- 违规成本

当前系统里这些能力已经部分存在，可以作为后续生活经济的惩罚层。

## 当前实现边界

这一点很重要：当前代码里，钱的变化已经是统一的，而且“生活费/房租/住房等级”已经落地为第一版系统。

现状如下：

- `money` 只作为余额存在。
- 消费主要来自商店、贷款、典当、赛事与个别事件。
- `applyMoneyTransaction` 会直接修改 `player.stats.money`，下限是 0。
- 已有额外的住房字段，也有周结算自动扣费。

因此，本设计稿里的“住房层级”和“固定生活开销”在第一版已经支持，后续只扩展更复杂的城市、房产与身份资产玩法。

## 现有商店平衡提醒

当前商店里，部分消耗品的即时恢复效率已经明显高于高价服务：

- `energy-drink`：3K，疲劳 -14
- `meal-kit`：3K，疲劳 -10、压力 -4
- `painkiller`：6K，疲劳 -22，并带短期恢复 buff
- `massage-therapy`：35K，疲劳 -20、压力 -15

这说明当前版本里，消耗品更像“高性价比的即时补丁”，而 35K 的理疗更像“贵但偏稳的服务项”。如果后续再叠加住房恢复、固定生活费或更多经济压力，必须避免直接把消耗品继续做成全时期最优解。

设计上建议：

- 消耗品保留“便宜、快、效率高”的定位，但要受每周限购和副作用约束。
- 服务类项目必须提供“更稳定、更长期、带额外收益”的价值，而不是只看单次恢复数值。
- 高价服务的主要价值应该放在压力整理、长期 buff、恢复上限或事件解锁，不应只和消耗品比即时数值。
- 若后续新增住房恢复或固定生活费，优先让它们和服务类项目形成层级关系，而不是把消耗品继续抬高。

## 消耗品副作用池

为了避免所有消耗品都变成“当前收益 + 下一回合 AP 预支”这种单一模板，消耗品副作用需要拆成多个池，并按物品类型轮换使用。

目标原则：

- 不同消耗品可以有不同副作用。
- 同一种消耗品的副作用最好固定在 1-2 类，便于玩家学习。
- 副作用要和物品语义一致，而不是为了惩罚而惩罚。
- 消耗品可以很强，但不能是纯净收益。
- 副作用优先复用当前商店支持的能力：`negativeEvents`、临时 buff、tag 增删，而不是先上新框架。

生命周期规则：

- 副作用必须有明确持续时间，默认以 1-3 个回合为主。
- 若副作用表现为 tag，必须有自动过期或可清除路径，不能永久挂到整局结束。
- 若副作用表现为 buff，必须写清楚使用次数、结束条件和是否可叠加。
- 若副作用表现为后续支出，必须明确触发条件与上限，避免滚雪球式失控。
- 同一物品的副作用不要求每次随机到完全不同，但应该在同一语义簇内轮换。

可用的副作用方向：

- `体感反弹`：当前回合恢复有效，但下回合压力小幅上升。
- `手感透支`：当前疲劳下降明显，但下回合成长效率下降。
- `胃口负担`：当前恢复更快，但下回合钱额外少一点。
- `药效回落`：当前很强，但连续使用时效果递减。
- `依赖标记`：短期 buff 很强，但会刷出“难以戒掉”类 tag。
- `比赛钝化`：当前不影响训练，但下一场比赛 rating / feel 略降。
- `恢复空窗`：本周恢复收益高，但接下来 1 回合不能再吃同类消耗品。
- `睡眠紊乱`：当前压力降得多，但下回合疲劳回升更快。
- `肠胃不适`：恢复类食物有效，但会带轻微 fatigue / stress 反向波动。
- `现金出血`：便宜恢复品给即时收益，但触发小额后续支出。

默认映射原则：

- `energy-drink`：恢复快、代价偏身体层面，所以以 `体感反弹` 为主。
- `meal-kit`：偏生活消耗，所以以 `胃口负担`、`现金出血` 为主。
- `painkiller`：偏硬压身体反馈，所以以 `手感透支`、`依赖标记` 为主。
- `massage-therapy`：偏高价稳定恢复，所以以 `恢复空窗`、`比赛钝化` 为主。

建议映射：

- `energy-drink`：`体感反弹` / `睡眠紊乱`
- `meal-kit`：`胃口负担` / `现金出血`
- `painkiller`：`手感透支` / `依赖标记`
- `massage-therapy`：`恢复空窗` / `比赛钝化`

如果后续再引入更多消耗品，可以继续往这个副作用池里分配，而不是把同一个副作用机械复用到所有物品上。

## 周结算时序建议

为了和当前引擎的工资逻辑保持一致，生活费和住房效果建议统一在周推进节点处理：

1. 先完成周推进。
2. 再处理工资到账和其他固定收入。
3. 再扣除生活费、房租、贷款类周期支出。
4. 最后处理恢复、事件和状态回写。

这样做的好处是：

- 薪资和生活成本都走同一个账期。
- 家人危机、破产检查等现有逻辑更容易复用。
- 玩家在同一回合内看到的现金变化更容易理解。

## 住宿事件展示

住宿系统的轻量波动和带抉择事件，建议分成两层展示：

- **纯结果型波动**：放在周结算里直接展示，例如“睡不好”“被打扰”“环境差”导致的疲劳 / 压力变化。
- **带选择的住宿事件**：以事件卡形式出现，例如“是否临时换住处”“是否花钱升级环境”“是否忍一周”。

这样做可以保证：

- 常规环境波动不打断主流程。
- 有决策意义的住宿问题才进入事件交互。
- 住宿档位同时影响结算日志和事件池权重。

## 分阶段实施

### 第一阶段：基础住房与房租

- 增加住宿等级字段。
- 提供宿舍 / 合租、普通租房、标准公寓、高端公寓、自有房产五档。
- 每档只定义基础周支出、恢复修正、压力修正。
- 玩家可在周推进节点主动切换住宿档位。
- 切换住宿时收取一次搬家成本，避免无成本来回换档。

### 第二阶段：住宿波动与室友事件

- 低档住宿接入住处波动事件。
- 事件以周结算日志和事件卡两种形式展示。
- 轻量结果进入周结算，带抉择结果走事件卡。
- 室友、噪音、停水、断网、催租等事件只放在低档和中档住宿。

### 第三阶段：房产与身份资产

- 已实现：自有房产从“可购买的住宿档位”升级为“可经营的身份资产”。
- 已实现：开放训练室、复盘室、休息室等附属功能，玩家可在自有房产中投入装修升级。
- 已实现：房产可承接家庭来访、装修、邻里、资产保值类事件。
- 已实现：房产的周期开销、设施维护成本和稳定恢复加成已经在周结算中明确。

### 第四阶段：地区与长期资产

- 已实现：不同常驻城市对同档住房有不同价格带和事件权重。
- 已实现：支持房产出租、抵押、卖房、装修等长期资产玩法。
- 已实现：城市系统和资产系统已接入住房周结算、事件权重和前端资产操作入口。

### 第五阶段：战队地区与赛事城市联动

- 已实现：战队地区优先作为玩家的赛事出行基准；没有战队时，使用当前住房城市档位作为常驻基准。
- 已实现：赛事周会读取当前 `pendingMatch` 对应赛事的城市 / 地区，生成临时驻地结算。
- 已实现：异地赛事周不再重复扣常驻生活费和常驻房租，改为一次性临时驻地成本。
- 已实现：临时驻地成本按住房档位、赛事是否有明确城市、是否跨地区参赛计算。
- 已实现：跨地区参赛时，自有房产出租收入暂停；同地区赛事周仍按常驻生活费、房租和房产收益正常结算。
- 已实现：房产抵押还款、设施维护、装修维护仍继续结算，避免跨城参赛变成逃避资产义务。
- 已实现：旅行周会写入 `travel-away`、`travel-city`、`travel-cross-region` 等短期 tag，事件池可以触发“酒店太吵”“临时训练室条件差”“时差没调过来”等恢复事件。

## 落地原则

- 新人阶段要有明显压力，但不能硬卡死。
- 住宿升级和短期恢复道具要分开。
- 住房收益要小而稳定，别压过赛事、训练和贷款。
- 购房是资产型选择，不应替代职业成长的核心玩法。
- 现有金钱流、贷款流、商店流、工资流都应保持可用。
- 房租、生活费、差旅费、赛事城市成本分别计入，不要重复扣同一项开销。

## 地区基准优先级

为了避免“战队地区 / 赛事城市 / 常驻城市”混用，长期居住和赛事出行分开判断：

- **长期居住基准**：常驻城市优先，用于房租、房产收益、住房事件权重和资产价值。
- **赛事出行基准**：有战队时优先使用战队地区；没有战队时使用当前住房城市档位。
- **赛事城市**：只在参赛期间影响临时住宿、差旅与恢复成本。
- **出生地区**：只作为角色背景和早期机会池来源，不直接提供硬数值加成。

房产收益只跟常驻城市和长期驻留状态相关；跨城参赛时，房产收益衰减或暂停。

默认归属规则：

- 自由人、待入队、转会中玩家，常驻城市默认跟随最近一次稳定居住档位。
- 如果没有稳定居住记录，则默认归属为当前战队地区对应城市群。
- 若当前没有战队，则默认归属为玩家出生地区或当前长期活动地区。

出生地区的作用：

- 决定玩家最初的背景归属和家乡叙事。
- 影响早期可见的机会池，例如本地青训、本地公开赛、熟人引荐、地区试训。
- 影响家人、朋友、熟人网络相关事件的权重。
- 离开出生地区后，可能增加适应成本、想家和环境不适类事件。
- 只影响路线和成本，不直接给数值优势，避免出生地成为最强开局选择。

# 特质长期辨识度设计方案

落地日期：2026-06-17

当前分支：`feature/team-management-actions`

状态：设计稿，待分阶段实施

## 1. 背景

当前特质已经能影响开局属性、事件标签和部分检定，但随着玩家核心属性成长，特质差异会逐渐被高属性覆盖。

典型问题：

- `枪法天才` 到中后期只是早期敏捷更高，最终会被普通高敏捷玩家追平。
- `战术大脑` 和普通高智力玩家在队伍事件中的差异不够稳定。
- `玻璃腕`、`夜猫体质` 这类缺陷或生活习惯型特质，玩家属性成长后长期风险不足。
- 事件池虽然已有 tag 概念，但 tag 对事件权重、选项后果和系统倍率的影响还不够成体系。

特质需要从“开局数值修正”升级为“选手身份系统”。玩家后期数值变强以后，仍然应该能感受到自己是枪男、指挥、团队型选手、媒体型选手、玻璃体质选手或训练狂。

## 2. 设计目标

- 特质影响不应被属性成长完全抹平。
- 不为 22 个特质分别硬写 22 套独立规则，而是优先用 tag 聚合长期效果。
- 长期效果必须接入已有系统：训练、比赛、状态、事件、队伍关系。
- 正面特质提供持续优势，负面特质提供可管理的长期风险。
- UI 需要让玩家知道特质长期影响，而不是只能看到开局属性。
- 数值改动必须可测试，避免隐形叠乘导致中后期失控。

## 3. 设计原则

### 3.1 特质三层结构

每个特质由三层组成：

1. 开局属性层
   - 影响初始面板。
   - 只服务早期差异。

2. 长期被动层
   - 由 trait tags 派生。
   - 持续影响疲劳、压力、训练收益、比赛表现或队伍关系。

3. 事件倾向层
   - 影响事件权重、可用选项、检定修正和后果。
   - 决定玩家更容易遇到哪类人生和职业问题。

### 3.2 以 tag 为规则单位

单个特质仍然保留文案和属性修正，但长期规则主要挂在 tags 上。

例如：

```text
枪法天才 = aimer + mechanical
玻璃腕 = fragile
天梯之王 = solo + mechanical
训练狂 = grinder + steady
```

这样做的好处：

- 多个相似特质能共享系统能力。
- 后续新增特质时，只要组合 tags，就能自动获得长期差异。
- 避免每个特质都写特殊分支。

### 3.3 长期效果要有代价边界

正面 tag 不应只给无脑增益，负面 tag 也不应只是惩罚。

示例：

- `solo`：个人表现上限更高，但队伍默契成长更慢。
- `grinder`：训练收益更高，但疲劳增长也更高。
- `fragile`：低疲劳时仍能发挥，高疲劳时伤病风险显著上升。
- `media`：名气机会更多，但舆论事件更多。

## 5. 系统接入设计

### 5.1 新增 traitEffects 派生层

新增模块建议：

```text
backend/src/engine/traitEffects.ts
```

职责：

- 从 `player.traits` 读取 trait。
- 聚合 trait tags。
- 输出标准化长期效果。

示意接口：

```ts
interface TraitEffectProfile {
  tags: Set<string>;
  fatigueGainMultiplier: number;
  stressGainMultiplier: number;
  trainingGrowthMultiplierByKey: Partial<Record<StatKey, number>>;
  checkBonusByContext: Partial<Record<string, number>>;
  matchModifiers: {
    headshotRateDelta?: number;
    ratingDelta?: number;
    clutchStressMultiplier?: number;
    volatility?: number;
  };
  eventWeightTags: Record<string, number>;
}
```

实现原则：

- 默认值为中性。
- 多个 tag 可叠加，但要 clamp。
- 高风险倍率必须有限制，例如总倍率控制在 `0.75 - 1.35`。

### 5.2 接入 stateModifiers

目标：让特质长期影响压力和疲劳。

示例规则：

- `steady`：压力正向增量 `* 0.9`
- `fragile`：疲劳高于 70 时压力正向增量 `* 1.1`
- `athletic`：疲劳正向增量 `* 0.88`
- `grinder`：训练行动疲劳正向增量 `* 1.08`
- `obsessed`：连续训练或高疲劳训练时压力正向增量 `* 1.12`
- `clutch`：比赛失败压力增量 `* 0.92`

验收标准：

- 同属性、同事件下，不同 tag 的疲劳/压力结果不同。
- 不出现负疲劳、负压力或倍率失控。

### 5.3 接入 resolver 检定

目标：让特质影响事件选择结果。

示例规则：

- `tactical`：训练、赛前准备、队伍战术类检定 `+1`
- `igl`：指挥权、队伍会议、战术冲突类检定 `+1`
- `media`：采访、粉丝、赞助类检定 `+1`
- `anti-media` / `shy`：采访类检定 `-1`，但舆论压力后果降低
- `risky` / `gambler`：高风险选项成功收益提高，失败资源损失提高
- `support` / `selfless`：队伍信任和队友默契收益提高
- `ego` / `solo`：个人选择更强，团队关系收益降低

验收标准：

- 检定日志或结果能解释 tag 修正。
- 特质不直接覆盖主属性，主属性仍是主要变量。

### 5.4 接入 matchSimulator

目标：让同属性玩家在比赛中因特质不同而表现不同。

示例规则：

- `aimer`：爆头率 `+0.03`，击杀上限略高。
- `mechanical`：rating 波动上限略高。
- `clutch` / `steady`：关键局或失败局压力惩罚降低。
- `solo`：个人 rating 略高，但团队协同收益略低。
- `support`：个人击杀略低，但团队胜率或队伍稳定性略高。
- `inconsistent`：rating 方差提高。
- `awper`：高击杀高死亡分布更常见，特定地图/对手事件可加权。

验收标准：

- 同属性、同状态、同赛事下，`aimer` 与普通玩家的 HS% / rating 分布有可测差异。
- `support` 不应简单变弱，而是从个人数据转移到团队结果。

### 5.5 接入事件权重

目标：让特质决定玩家更常遇到哪类事件。

事件权重示例：

- `media`：舆论、采访、粉丝、赞助事件权重提高。
- `fragile`：伤病、恢复、带伤上场事件权重提高。
- `grinder` / `obsessed`：训练透支、恢复选择、生活失衡事件权重提高。
- `igl` / `tactical`：战术复盘、指挥权、队伍政治事件权重提高。
- `solo` / `ego`：队伍冲突、角色冲突、转会传闻事件权重提高。
- `support` / `selfless`：队友关系、背锅、团队修复事件权重提高。

验收标准：

- 事件权重只影响出现概率，不让单一事件刷屏。
- 有冷却和近期事件去重。

## 6. UI 展示

### 6.1 开局特质展示

当前只展示属性加减和描述。需要新增“长期影响”区域。

示例：

```text
枪法天才
开局：敏捷 +3
长期：枪法训练收益略高；比赛爆头倾向提高；更容易触发高光事件
标签：aimer / mechanical
```

### 6.2 生涯内特质面板

玩家详情或 HUD 附近展示：

- 当前特质。
- 长期被动摘要。
- 当前触发中的 trait 效果。

避免展示过细倍率，优先展示可理解文案。

## 7. 分阶段实施

### 阶段 1：traitEffects 基础层

目标：建立统一派生层，不立即大改事件内容。

范围：

- 新建 `traitEffects.ts`。
- 聚合玩家 tags。
- 输出疲劳、压力、训练、比赛的标准 modifier。
- 为核心 tags 添加第一批倍率。

建议先覆盖 tags：

- `aimer`
- `mechanical`
- `tactical`
- `steady`
- `fragile`
- `grinder`
- `athletic`
- `solo`
- `support`

接入点：

- `stateModifiers.ts`
- `resolver.ts` 的成长倍率或检定修正
- 单元测试

验收：

- 同属性玩家，带 `steady` 与不带 `steady` 的压力结果不同。
- 带 `fragile` 的玩家高疲劳下风险更高。
- 带 `grinder` 的玩家训练收益或疲劳成本不同。

### 阶段 2：比赛表现差异

目标：让特质影响比赛数据和胜负转化。

范围：

- 接入 `matchSimulator.ts`。
- 为比赛相关 tags 加小幅稳定修正。
- 更新比赛结果文案或 passive effects，让玩家知道特质生效。

优先 tags：

- `aimer`
- `mechanical`
- `clutch`
- `steady`
- `solo`
- `support`
- `awper`
- `inconsistent`

验收：

- 同属性 `aimer` 玩家 HS% 分布略高。
- `support` 玩家个人数据不一定更高，但团队结果稳定性更好。
- `inconsistent` 玩家 rating 方差更大。

### 阶段 3：事件权重系统

目标：让特质影响玩家遇到的事件类型。

范围：

- 扩展事件 pick 候选权重。
- 为事件增加 tag affinity 配置。
- 保留冷却和近期事件去重。

优先事件域：

- 媒体/粉丝/赞助。
- 伤病/恢复。
- 训练透支/生活失衡。
- 队伍政治/角色冲突。

验收：

- `media` 玩家更常遇到采访和舆论。
- `fragile` 玩家更常遇到伤病和恢复。
- `igl` 玩家更常遇到指挥和战术事件。

### 阶段 4：专属事件和选项

目标：补内容，让特质不只是倍率。

范围：

- 每个特质类别补 1-2 个专属事件。
- 部分事件增加 tag 专属选项。
- 成功和失败都要有不同后果。

特质类别：

1. 天赋型：枪法天才、战术大脑、冰冷心脏、铁打身板。
2. 打法型：AWP 嗅觉、团队型选手、天梯之王、花架子、急性子。
3. 性格型：自负、社恐、易怒、背锅侠、赌徒体质。
4. 生活习惯型：训练狂、沉迷型、拖延症、夜猫体质。
5. 缺陷型：玻璃心、玻璃腕。

验收：

- 每类至少有可感知的专属事件。
- 不同特质路线的生涯叙事明显不同。

### 阶段 5：前端展示和调参

目标：让玩家理解长期效果，并通过数据调平衡。

范围：

- 开局特质卡展示长期影响。
- 玩家详情显示 trait 被动摘要。
- 比赛/事件结果显示关键 trait 触发。
- 增加调试面板或日志字段辅助平衡。

验收：

- 玩家能在 UI 上看到“为什么这个特质有用”。
- 测试或调试数据能观察 tag 对疲劳、压力、训练和比赛的影响。

## 8. 示例设计

```text
tags：aimer, mechanical

- 敏捷高位成长衰减略慢
- 比赛爆头率倾向小幅提高
- 高光事件权重提高
风险：
- 如果智力或心态不足，更容易触发“被针对”“只靠枪法”类事件
```

```text
风险：
- 如果队伍信任低，战术分歧更容易升级为冲突
```

```text
- 高疲劳时伤病风险显著提高
- 理疗和恢复服务收益提高
风险：
- 强练、连续比赛、带伤上场更容易触发长期恢复成本
```

```text
开局：敏捷 +2，智力 -1

长期：
- 个人 rating 倾向提高
- 天梯和个人高光事件权重提高
- 队友默契成长降低
风险：
- 队伍政治和角色冲突事件权重提高
```

### 8.5 团队型选手

```text
开局：心态 +1，智力 +1
tags：support, steady
长期：
- 队友默契收益提高
- 队伍信任收益提高
- 失败时压力略低
风险：
- 个人高光和名气收益略低
```

## 9. 风险与控制

### 9.1 倍率叠加过强

控制方式：

- 所有倍率聚合后 clamp。
- 第一阶段每个 tag 只给 5%-12% 的小修正。
- 不同系统分开测，不同时大幅加成训练、比赛和事件。

### 9.2 负面特质太痛苦

控制方式：

- 负面特质必须有管理路径。
- 商店、休息、队伍管理或事件选择能降低风险。
- 负面不应永久锁死一局游戏。

### 9.3 UI 信息过载

控制方式：

- 开局只展示摘要。
- 详细倍率放调试或 tooltip。
- 结果页只显示本次真正触发的关键 trait 效果。

## 10. 推荐实施顺序

建议按以下顺序推进：

1. 阶段 1：traitEffects 基础层。
2. 阶段 2：比赛表现差异。
3. 阶段 5 的最小 UI：开局特质长期效果摘要。
4. 阶段 3：事件权重系统。
5. 阶段 4：专属事件和选项。
6. 阶段 5 完整 UI 和调参工具。

原因：

- 先做统一派生层，后续内容和 UI 都能复用。
- 比赛差异最容易被玩家感知。
- 事件权重和专属事件内容量大，适合在系统稳定后逐步补。
